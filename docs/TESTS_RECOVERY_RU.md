# Исправление тестов service-common

## Что произошло

В Git-коммите `4f10a4d` («Добавление сервиса очередей») содержимое большого количества тестовых файлов было **заменено на пустое**. Это не только отключенные `*Test.java`: обнулились и классы DTO, вспомогательные типы и SQL-скрипты, которые нужны оставшимся тестам для компиляции/запуска.

Этот патч восстанавливает оригинальные файлы из предыдущего коммита **`b3a6df6`**, без реконструкции по догадкам:

- **23 тестовых DTO** в `src/test/java`;
- **4 вспомогательных Java-типа**: `CrudCompositeKey`, `ItDocumentKind`, `ItDocumentState`, `TestComplexState`;
- **`SecurityTestContainer`**, который используется активным `AuditEdgeCasesExploreTest`;
- **4 SQL-скрипта** из `src/test/resources/db`, необходимые для Testcontainers.

Остальные пустые тестовые классы и неиспользуемые тестовые ресурсы **не восстановлены** — чтобы случайно не включить десятки ранее выключенных тестов.

## Установка

1. Сохраните/закоммитьте текущие изменения, особенно в `service-common/pom.xml`.
2. Распакуйте ZIP в корень `D:\Projects\AtomSkills` с сохранением относительных путей. Архив содержит папку `service-common/`.
3. В `pom.xml` оставлена ранее добавленная зависимость `spring-boot-starter-mail`; никаких файлов почтового модуля патч не заменяет.
4. Обновите Maven в IntelliJ IDEA.

## Режимы сборки

В `pom.xml` настроены `<skipTests>true</skipTests>` и `maven-surefire-plugin` (`<skipTests>${skipTests}</skipTests>`).

```powershell
cd D:\Projects\AtomSkills\service-common

# По умолчанию: тесты компилируются, но не запускаются
.\mvnw.cmd clean install

# Запустить тесты явно
.\mvnw.cmd test -DskipTests=false

# Проверить все тесты при install
.\mvnw.cmd clean install -DskipTests=false

# Быстрая установка без запуска И без компиляции тестов
.\mvnw.cmd clean install -Dmaven.test.skip=true
```

**Важно:** активные интеграционные тесты используют PostgreSQL через Testcontainers и требуют работающий Docker.

### Что отличается от `-DskipTests`

`-DskipTests` пропускает запуск, но **всё равно компилирует тестовые классы** — поэтому недостающие DTO действительно нужно восстановить. `-Dmaven.test.skip=true` пропускает как компиляцию, так и запуск.

## Проверки и ограничения

- Из Git восстановлены реальные исходники классов и SQL, а не заглушки.
- Проверена целостность всех восстановленных файлов и XML-синтаксис `pom.xml`.
- Сверены имена пустых Java-файлов с обращениями из непустых исходников: все найденные отсутствующие типы, на которые ссылается действующий тестовый код, включены в патч.
- **Полную Maven-сборку, Docker/Testcontainers и тесты в среде подготовки патча запустить не удалось.** При появлении новой ошибки сборки понадобится её лог и актуальное состояние рабочего дерева после установки патча.
